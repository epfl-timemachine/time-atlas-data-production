## V1.0 (XX-12-2024)

#### Homogenisation with the latest Data Model:
* PoI no longer have time data (start_time, end_time), time data is present on the Obs.
* In HR the “metadata” field now is called “annotated_content”.
* In obs, ”part_of” is now generated and the data and has been renamed “has_handle”, it is no longer an array  but a single value (reflects the cardinality of the schema).
* The field that links the Obs to the geometry is now called “has_geometry”, and no longer features the layer_uuid (it is already present in the geometry object and generated there on the fly by the backend).
* Links from Obs to HR are no longer an array, but a single value (reflects the cardinality of the schema)
* Both geometrical and background layer have the same data modelling, only the “type” field make them distinguish (before, the geometrical layer did not have a “layer_configuriton” object).
* in the dataset configuration file, the "verbs" field no longer exists, instead boolean parameters "short_display" and "hidden" are specified for each field, like with "indexable".

#### Cleanup:
* Areas are now in their own folder “areas”
* All datasets are now in their own `datasets` folder
* map and layers are now split into their own separate file. 

#### Validation:
* in the folder `validation/schemas`, there are JSON Schema validating the basic structure of all the type of data object from the data model
* a script `validation/validate_data.py` takes care of comparing all generated data against the schema and inform the user if it is valid.

#### New Additions:
* Now there is a “thumbnail” field in all layers, links to a IIIF link to a custom thumbnail view of the layer to be displayed in the interface. 
* There is also a “publish” field in the dataset, containing information to generate a “Zotero/Cite me” link
* The link from HR to Obs are now tuples, the first value stays the uuid of the PoI, while the second value indicate which fields from the HR the obs location stems from (way to resolve the 1 to many display issue with obs/HR, for now only mattering in Garzoni’s case) 

#### Slug:
* Slug & Uuid now present for datasets, maps and layers. I guess it makes sense that the “id” (i.e. url) should be generated by the backend for all those objects. 
* Now HR, Ops and Configuration has an object “dataset” 

#### Multilingual:
* In the dataset RDE, name, description and paradata are now multilingual, following the structure of multilingual implementation by the IIIF protocol ({“lan”: [“value”]}
* Map and layers also have mulitlingual entries for the name and description
* Label at the manifest level are now in 3 languages, English French and Italian (translation were provided by Github Copilot, I could check their accuracy in French, but not Italian).
* In the configuration file, all display labels are now also in the 3 languages. 

#### UUID changes:
* With that much changes, some uuid have change, mainly the uuids of all layers, and all data generated in Garzoni and the UUID of the PoI and Obs of Catastici. Otherwise all other UUID should have stayed the same. 

#### Misc:
* "falls_within" for datasets and maps now link to their area using the UUID of the area rather than the slug/name.§
